**Reading the `Verify:` numbers.** Each one records what was observed when that group
was verified, at that group's commit. They are a log, not a reproducible assertion:
groups 11–15 added tests to targets groups 1–10 had already counted, so re-running an
early command today prints a larger number. Where a number has moved, the current one
is in parentheses beside it — measured at the head of this branch (`cargo test` → 160;

## 11. Post-audit: the args[0] contract, `argv_tail`, and removing `argv` (D12)

## 12. Post-audit: two wrong-allow holes — subcommand position and raw endpoint paths (D14, D15)

Adversarial security audit findings, both reproduced against the running daemon. (1) `10-git:git-read-only` tested set membership, which cannot express POSITION, so `git -c core.fsmonitor=<cmd> status` was allowed — and git runs `<cmd>`, i.e. arbitrary code execution behind a "read-only git" permit. `argv_tail` (task 11) is the primitive that can express position: it strips `args[0]`, so its first token IS the subcommand. (2) endpoint `path` reaches policy raw and still percent-encoded, so `resource.path like "/repos/*"` — the shape the design doc, the README and the tests all use — was satisfied by `/repos/../user/keys`, which a normalising origin serves as `/user/keys`.
